## Revised local M1–M3 acceptance contract v1 (2026-10-23)

This dated, scoped amendment supersedes the historical M1–M3 acceptance criteria only for delivery of the bounded local-library product slice. It does not change `idea.md`'s wider vision or mark any historical test, scale target, qualification, or GUI gate as passed. The chosen path remains SQLite/WAL/FULL and egui/eframe, with existing ADR-001 qualification before production GUI admission. At amendment time, Hound `=3.5.1`, Claxon `=0.4.3`, and nanomp3 `=0.2.0` were conditional planning choices, not dependency admission. The coordinated M2 decoder policy has since been reviewed and integrated in `docs/adr/004-crate-boundaries.md` and `docs/layers-policy.md`; the executable layer gate enforces it. See the M2 closeout below. Production GUI admission, vendor interoperability, and representative-scale qualification remain separate gates.

The local catalog is versioned, reference-only, single-process, local-filesystem and capped at 10,000 tracks. This is a scope boundary, not measured capacity or evidence of performance, crash durability, or scale. It imports no personal media into the repository or attachments. Only owner-authorized samples may be used in private local smoke tests; originals must remain unchanged.

### MVP-first verification scope (2026-10-31)

Keep the existing bounded M1–M3 acceptance and its required application smoke/review gates. Do not make extra per-widget geometry harnesses, broad viewport matrices, performance benchmarks, or 500k-item stress runs prerequisites for a running MVP. Defer those fine-grained and scale validations until an MVP product is running; retain 500k/60fps as an unpassed later qualification gate. Add narrow verification only when it proves a user-visible MVP defect, and prefer the smallest fix over surrogate evidence that does not exercise the app.

Owner deferral (2026-10-31): feature-specific synthetic regression tests and fresh Bot Screen smoke for the provisional read-only XML preview are deferred to later UI validation. The smoke is NOT RUN because Bot Screen launch failed with `XOpenDisplayFailed`; existing UI tests and `cargo xtask ci` do not prove the new preview path. Do not treat the preview as verified or claim the deferred checks passed.
