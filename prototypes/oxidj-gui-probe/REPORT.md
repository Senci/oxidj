# ADR-001 isolated egui probe — evidence report

Status: **NOT PASSED / NOT QUALIFYING**. This probe is isolated; no GUI dependency was added to the root workspace or production manifests. No personal media was opened.

## Environment and build

- Host: Linux `viper`, x86_64, kernel `7.2.5-3-omarchy`; Wayland session, `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-1`.
- Rust `1.99.0 (b940084d7 2026-09-28)`, Cargo `1.99.0 (5f94df478 2026-08-27)`.
- Probe: `prototypes/oxidj-gui-probe`, standalone Cargo workspace, eframe `=0.32.3`, explicit `accesskit` feature.
- Build/run command: `WAYLAND_DISPLAY=wayland-2 cargo run --offline --manifest-path prototypes/oxidj-gui-probe/Cargo.toml -- 200000` (500k: replace final argument with `500000`). The probe reports after 15 seconds and leaves its window open. Rows are deterministic synthetic labels rendered using `ScrollArea::show_rows` with 24-pixel row height. In the separate nested Wayland session, 200k reported 341 update callbacks / 16,072ms = 21.2 callback/s after one End key; 500k reported 454 / 15,010ms = 30.2 callback/s after one End key. Both reached the last row with matching widget focus and nonzero scroll offsets. At 500k, Shift+Up twice produced `Focused row: 499995 | selected: 4`; plain Up produced row 499994 with one selected row. Two Ctrl+Space attempts left the visible selection count at 1; keyboard toggle was not demonstrated. A screenshot showed the 500k focused row and range visibly highlighted; both probe windows remain open. These are callback counts around sparse navigation events, not sustained-scroll workload or presented-frame measurements. The earlier probe was not reopened after its auto-close; the user later authorized this separate nested Wayland session. Host workspace and display mode were untouched. The host Hyprland mode remains 3840×2160@30Hz; 1920×1080@60Hz and 2560×1440@59.95Hz are available but were not activated. 60fps performance remains unmeasured.

## Sustained-scroll frame-observation attempt (2026-10-24)

No actual-frame measurement was obtained; callback rates above are not substitutes. The already-running probes are in the nested Hyprland session (`WAYLAND_DISPLAY=wayland-2`), whose virtual output reports 1581×868@60Hz. A direct output capture with `WAYLAND_DISPLAY=wayland-2 XDG_RUNTIME_DIR=/run/user/1000 grim ...` did not return within 2 seconds (`timeout` exit 124; also reproduced with a 5-second timeout). The available `computer_use` screen capture instead targets the host display and failed with X11 `GetImage` error 8; it did not capture the nested output. `wf-recorder`, `wayland-info`, and `wlr-randr` are not installed. Thus the precise missing capability is a working capture/recording path for the nested compositor output (or a compositor presentation-timing source), not input/focus control or display refresh selection. Sustained scrolling and presented frames remain NOT MEASURED at both 200k and 500k. No callback count is re-labelled as a frame rate.

This is isolated probe evidence, not evidence that ADR-001's production gates pass. Sustained-scroll/presented-frame performance and real screen-reader/platform checks remain unqualified. Do not admit the framework to production from this report.
