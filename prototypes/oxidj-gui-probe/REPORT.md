# ADR-001 isolated egui probe — evidence report

Status: **NOT PASSED / NOT QUALIFYING**. This probe is isolated; no GUI dependency was added to the root workspace or production manifests. No personal media was opened.

## Environment and build

- Host: Linux `viper`, x86_64, kernel `7.2.5-3-omarchy`; Wayland session, `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-1`.
- Rust `1.99.0 (b940084d7 2026-09-28)`, Cargo `1.99.0 (5f94df478 2026-08-27)`.
- Probe: `prototypes/oxidj-gui-probe`, standalone Cargo workspace, eframe `=0.32.3`, explicit `accesskit` feature.
- Build/run command: `WAYLAND_DISPLAY=wayland-2 cargo run --offline --manifest-path prototypes/oxidj-gui-probe/Cargo.toml -- 200000` (500k: replace final argument with `500000`). The probe reports after 15 seconds and leaves its window open. Rows are deterministic synthetic labels rendered using `ScrollArea::show_rows` with 24-pixel row height. In the separate nested Wayland session, 200k reported 341 update callbacks / 16,072ms = 21.2 callback/s after one End key; 500k reported 454 / 15,010ms = 30.2 callback/s after one End key. Both reached the last row with matching widget focus and nonzero scroll offsets. At 500k, Shift+Up twice produced `Focused row: 499995 | selected: 4`; plain Up produced row 499994 with one selected row. Two Ctrl+Space attempts left the visible selection count at 1; keyboard toggle was not demonstrated. A screenshot showed the 500k focused row and range visibly highlighted; both probe windows were reported open at the end of that earlier session, but no probe window is open in the current continuation. These are callback counts around sparse navigation events, not sustained-scroll workload or presented-frame measurements. The earlier probe was not reopened after its auto-close; the user later authorized this separate nested Wayland session. Host workspace and display mode were untouched. The host Hyprland mode remains 3840×2160@30Hz; 1920×1080@60Hz and 2560×1440@59.95Hz are available but were not activated. 60fps performance remains unmeasured.

## Sustained-scroll frame-observation attempt (2026-10-24)

No actual-frame measurement was obtained; callback rates above are not substitutes. The first eframe-bound `wp_presentation_feedback` attempt used synchronous registry setup and roundtrips; it advanced only three update callbacks in about 20 seconds and emitted no feedback. The async observer then removed roundtrips and shared-display reads, but this did not prove feedback would arrive. Two older probe windows remained mapped in the nested session; neither used the revised build. A bounded live run of the revised 200k probe then timed out after 105 seconds with only three update callbacks and no report or feedback. This showed no usable evidence and was stopped.

As a distinct path, the standalone probe was built with `--features eframe/wgpu`, then run with `WGPU_BACKEND=vulkan` and `OXIDJ_PRESENT_SCROLL=1` at 200k rows. The run emitted `probe_finished rows=200000 update_callbacks=21 elapsed_ms=15095 callback_fps=1.4 keyboard_events=0 focused_row=110 widget_focused_row=Some(110) scroll_offset=2970.0 ... presentation_feedback_presented=0 presentation_feedback_unique_timestamps=0 presentation_fps=0.00 presentation_feedback_discarded=0 last_refresh_ns=None presentation_error=None`. The command ended at its 22-second timeout (exit 124); the report arrived at 15,095ms. This is callback and scroll-state evidence only, not frame-rate evidence. The requested Vulkan/WGPU path produced no presentation events or protocol error, so no 500k repeat was run. Actual sustained-scroll presented-frame rates remain NOT MEASURED at both sizes.

Earlier nested capture attempts (`WAYLAND_DISPLAY=wayland-2`) timed out with `grim` (exit 124), and host `computer_use` capture failed with X11 `GetImage` error 8. Do not re-label callback counts as frame rates. Presentation feedback remains unusable on this nested eframe surface; ADR-001 stays NOT PASSED and M3 remains gated.

This is isolated probe evidence, not evidence that ADR-001's production gates pass. Sustained-scroll/presented-frame performance and real screen-reader/platform checks remain unqualified. Do not admit the framework to production from this report.
