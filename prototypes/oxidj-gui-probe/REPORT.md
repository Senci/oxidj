# ADR-001 isolated egui probe — evidence report

Status: **NOT PASSED / NOT QUALIFYING**. This probe is isolated; no GUI dependency was added to the root workspace or production manifests. No personal media was opened.

Latest committed evidence: `058e205` records observer-free auto-scroll at both 200k and 500k rows, with visible progression in a 30fps portal recording. A fresh nested Hyprland run now returns presentation feedback for stationary rendering at both sizes (about 30fps), but feedback-enabled sustained scrolling remains unmeasured. The 30fps portal capture cannot establish app frame rate. Real screen-reader and supported-platform checks also remain outstanding. No framework gate or production admission is passed by this evidence.

## Environment and build

- Host: Linux `viper`, x86_64, kernel `7.2.5-3-omarchy`; Wayland session, `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-1`.
- Rust `1.99.0 (b940084d7 2026-09-28)`, Cargo `1.99.0 (5f94df478 2026-08-27)`.
- Probe: `prototypes/oxidj-gui-probe`, standalone Cargo workspace, eframe `=0.32.3`, explicit `accesskit` feature.
- Build/run command: `WAYLAND_DISPLAY=wayland-2 cargo run --offline --manifest-path prototypes/oxidj-gui-probe/Cargo.toml -- 200000` (500k: replace final argument with `500000`). The probe reports after 15 seconds and leaves its window open. Rows are deterministic synthetic labels rendered using `ScrollArea::show_rows` with 24-pixel row height. In the separate nested Wayland session, 200k reported 341 update callbacks / 16,072ms = 21.2 callback/s after one End key; 500k reported 454 / 15,010ms = 30.2 callback/s after one End key. Both reached the last row with matching widget focus and nonzero scroll offsets. At 500k, Shift+Up twice produced `Focused row: 499995 | selected: 4`; plain Up produced row 499994 with one selected row. Two Ctrl+Space attempts left the visible selection count at 1; keyboard toggle was not demonstrated. A screenshot showed the 500k focused row and range visibly highlighted; both probe windows were reported open at the end of that earlier session. These are historical observations, not a claim about current window state. These are callback counts around sparse navigation events, not sustained-scroll workload or presented-frame measurements. The earlier probe was not reopened after its auto-close; the user later authorized this separate nested Wayland session. Host workspace and display mode were untouched. The host Hyprland mode remains 3840×2160@30Hz; 1920×1080@60Hz and 2560×1440@59.95Hz are available but were not activated. 60fps performance remains unmeasured.

## Sustained-scroll frame-observation attempt (2026-10-24)

No actual-frame measurement was obtained in these historical attempts; callback rates above are not substitutes. The first eframe-bound `wp_presentation_feedback` attempt used synchronous registry setup and roundtrips; it advanced only three update callbacks in about 20 seconds and emitted no feedback. The async observer then removed roundtrips and shared-display reads, but this did not prove feedback would arrive. Two older probe windows remained mapped in the nested session; neither used the revised build. A bounded live run of the revised 200k probe then timed out after 105 seconds with only three update callbacks and no report or feedback. This showed no usable evidence and was stopped.

As a distinct path, the standalone probe was built with `--features eframe/wgpu`, then run with `WGPU_BACKEND=vulkan` and `OXIDJ_PRESENT_SCROLL=1` at 200k rows. The run emitted `probe_finished rows=200000 update_callbacks=21 elapsed_ms=15095 callback_fps=1.4 keyboard_events=0 focused_row=110 widget_focused_row=Some(110) scroll_offset=2970.0 ... presentation_feedback_presented=0 presentation_feedback_unique_timestamps=0 presentation_fps=0.00 presentation_feedback_discarded=0 last_refresh_ns=None presentation_error=None`. The command ended at its 22-second timeout (exit 124); the report arrived at 15,095ms. This is callback and scroll-state evidence only, not frame-rate evidence. The requested Vulkan/WGPU path produced no presentation events or protocol error, so no 500k repeat was run. Actual sustained-scroll presented-frame rates remain NOT MEASURED at both sizes.

Earlier nested capture attempts (`WAYLAND_DISPLAY=wayland-2`) timed out with `grim` (exit 124), and host `computer_use` capture failed with X11 `GetImage` error 8. Do not re-label callback counts as frame rates. A follow-up bounded protocol trace used `WAYLAND_DEBUG=client` for the same 200k WGPU/Vulkan run (22-second timeout, exit 124). The trace contained 21 client `wp_presentation.feedback(wl_surface#27, ...)` requests and zero incoming `wp_presentation_feedback.presented` or `.discarded` events; the probe's own 15,106ms report likewise recorded zero presented/unique timestamps, `presentation_fps=0.00`, no protocol error, and only 21 update callbacks. The trace therefore narrows the failure: requests are sent on the live surface, but this run receives no presentation-feedback event. It still provides no actual presented-frame rate and no sustained-scroll result; 500k was not retried. Needed capability is a compositor/native observer that can return actual presentation timestamps (or a verified alternate supported measurement source), not merely another request-side trace. Presentation feedback remains unusable on this nested eframe surface; ADR-001 stays NOT PASSED and M3 remains gated.

### Visibility-controlled retry (2026-10-24)

The first protocol trace ran while the existing nested Hyprland window was on inactive host workspace 2; host workspace 1 was active. Its `wl_surface#27` had six commits (one initial empty commit, five buffer attachments), all within 145ms. No later commit followed the observer requests. To test whether host-workspace visibility was responsible, the existing nested window was silently moved to active workspace 1 without switching workspaces, then restored to workspace 2. A second bounded 200k WGPU/Vulkan trace with `WAYLAND_DEBUG=client` was unchanged: six surface commits / five buffer attachments within 121ms, 16 observer feedback requests, five WGPU feedback requests, zero `presented` or `discarded` events, and zero protocol errors. The probe reported 21 callbacks / 15,111ms, scroll offset 2,970, and zero presentation feedback; timeout exit 124 at 22s. Both older probe windows remained open. Visibility alone did not restore commits or feedback; cause remains unproven. No actual frame-rate evidence was obtained. The host output remains 3840×2160@30Hz, so this setup also cannot qualify a 60fps gate. Do not repeat this measurement route without a changed compositor/measurement capability; ADR-001 remains NOT PASSED and M3 remains gated.

### Observer-free auto-scroll portal capture (2026-10-24)

To avoid the observer path that stalled eframe, `OXIDJ_PRESENT_SCROLL=1` enabled deterministic 100ms focus/scroll steps and disabled `PresentationObserver`. Fresh 200k and 500k WGPU/Vulkan runs each reported about 30 update callbacks/s, then reached focused row 119 with scroll offset 3213 after 15s. A portal recording captured the nested desktop at 3812×2100, constant 30fps. At 10s, sampled frames visibly showed auto-scroll progression (focused row 50 at 200k; row 42 at 500k). For each recording, FFmpeg `mpdecimate,showinfo` counted changed frames in a 1400×850 crop of the probe list: 200k had 136 changed frames across 11.967s (11.36 changes/s); 500k had 137 across 13.7s (9.93 changes/s). These are portal-sampled visible-content changes, not compositor presentation timestamps or app frame rates. The 30fps capture cannot establish performance at 60fps; both sustained-scroll presented-frame gates remain NOT MEASURED / NOT QUALIFIED. ADR-001 remains NOT PASSED and M3 remains gated.

### Fresh nested Hyprland stationary presentation run (2026-10-24)

The owner authorized one fresh isolated nested session. Host Hyprland was 0.56.2 with Aquamarine 0.15.1; the nested output resolved to 1517×832@60Hz while the host monitor remained 3840×2160@30Hz. The probe used the existing WGPU/Vulkan path with `auto_scroll_enabled=false` and presentation feedback enabled.

- 200k: 453 update callbacks / 15,000ms = 30.2 callbacks/s; 362 presented timestamps / 12,000ms = 30.17fps; 0 discarded; no observer error.
- 500k: 453 update callbacks / 15,019ms = 30.2 callbacks/s; 361 presented timestamps / 12,000ms = 30.08fps; 0 discarded; no observer error.

Each bounded command reached its 15-second report, then timed out at 35 seconds (exit 124) because the probe window stays open. These stationary rates do not satisfy the 60fps gate and do not measure sustained scrolling. ADR-001 remains NOT PASSED; M3 remains gated.

This is isolated probe evidence, not evidence that ADR-001's production gates pass. Sustained-scroll/presented-frame performance and real screen-reader/platform checks remain unqualified. Do not admit the framework to production from this report.
