## Sustained-scroll frame-observation attempt (2026-10-24)

No actual-frame measurement was obtained in these historical attempts; callback rates above are not substitutes. The first eframe-bound `wp_presentation_feedback` attempt used synchronous registry setup and roundtrips; it advanced only three update callbacks in about 20 seconds and emitted no feedback. The async observer then removed roundtrips and shared-display reads, but this did not prove feedback would arrive. Two older probe windows remained mapped in the nested session; neither used the revised build. A bounded live run of the revised 200k probe then timed out after 105 seconds with only three update callbacks and no report or feedback. This showed no usable evidence and was stopped.

As a distinct path, the standalone probe was built with `--features eframe/wgpu`, then run with `WGPU_BACKEND=vulkan` and `OXIDJ_PRESENT_SCROLL=1` at 200k rows. The run emitted `probe_finished rows=200000 update_callbacks=21 elapsed_ms=15095 callback_fps=1.4 keyboard_events=0 focused_row=110 widget_focused_row=Some(110) scroll_offset=2970.0 ... presentation_feedback_presented=0 presentation_feedback_unique_timestamps=0 presentation_fps=0.00 presentation_feedback_discarded=0 last_refresh_ns=None presentation_error=None`. The command ended at its 22-second timeout (exit 124); the report arrived at 15,095ms. This is callback and scroll-state evidence only, not frame-rate evidence. The requested Vulkan/WGPU path produced no presentation events or protocol error, so no 500k repeat was run. Actual sustained-scroll presented-frame rates remain NOT MEASURED at both sizes.

Earlier nested capture attempts (`WAYLAND_DISPLAY=wayland-2`) timed out with `grim` (exit 124), and host `computer_use` capture failed with X11 `GetImage` error 8. Do not re-label callback counts as frame rates. A follow-up bounded protocol trace used `WAYLAND_DEBUG=client` for the same 200k WGPU/Vulkan run (22-second timeout, exit 124). The trace contained 21 client `wp_presentation.feedback(wl_surface#27, ...)` requests and zero incoming `wp_presentation_feedback.presented` or `.discarded` events; the probe's own 15,106ms report likewise recorded zero presented/unique timestamps, `presentation_fps=0.00`, no protocol error, and only 21 update callbacks. The trace therefore narrows the failure: requests are sent on the live surface, but this run receives no presentation-feedback event. It still provides no actual presented-frame rate and no sustained-scroll result; 500k was not retried. Needed capability is a compositor/native observer that can return actual presentation timestamps (or a verified alternate supported measurement source), not merely another request-side trace. Presentation feedback remains unusable on this nested eframe surface; ADR-001 stays NOT PASSED and M3 remains gated.
