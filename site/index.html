Your local DJ library, built in Rust.

Your files stay yours.

Playlists, cues and beat grids can get stuck in one tool. OxiDJ aims to make moving them safer, without quietly losing the work behind a set.

We're starting small: audio stays where it is, while references and technical facts live in a local catalog. No cloud account needed. Dependable exchange comes before decks.

  1. M1: Local catalogPersistent IDs, technical facts, backup and recovery.
  2. M2: File importWAV, FLAC and MP3 references, with encoding-specific limits.
  3. M3: Prototype viewerSearch, sort, selection and saved-catalog reopen.

XML first. Hardware exchange later.

Rekordbox XML is a documented playlist interchange format. OneLibrary is a separate USB/SD library format used by compatible DJ hardware. XML support alone proves neither OneLibrary export nor complete Rekordbox round trips.

Try the CLI from source.

Linux is the exercised development platform. macOS and Windows are unverified; there is no CI validation for them. These are CLI instructions, rather than a packaged desktop release.

Install Git, Rust via rustup and a native C build toolchain (a compiler and linker). The repository selects its pinned Rust toolchain. Use a writable local disk for the catalog and a small test folder of audio. The single-process catalog has a 10,000-track scope limit. 

git clone https://github.com/Senci/oxidj.git
cd oxidj
cargo build -p oxidj-cli --locked
cargo run -p oxidj-cli -- --help

Create a catalog, import a folder, then list saved tracks. Replace /path/to/test-audio with your folder: 

cargo run -p oxidj-cli -- catalog init --db ./catalog.sqlite
cargo run -p oxidj-cli -- catalog import --db ./catalog.sqlite --dir /path/to/test-audio
cargo run -p oxidj-cli -- catalog list --db ./catalog.sqlite

Import leaves original audio unchanged and reports each file's result. Embedded DJ tags, artwork, editing and playback are outside this local slice. list prints track IDs, paths, digests and sizes. An empty catalog prints only the header.
