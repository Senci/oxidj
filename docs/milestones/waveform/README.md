# Waveform W4 — library UI captures (synthetic audio)

Real captures of the OxiDJ library UI on the isolated Bot Screen (X11, 1440x900,
full-screen composited grab via Hermes `computer_use`), 2026-11-03.

- Binary: `prototypes/oxidj-library-ui` release build from commit `8713512`
  (built after that commit; no UI/crate source changes since).
- Data: synthetic audio only, generated by [`gen_synthetic.py`](gen_synthetic.py)
  (124 bpm 55 Hz kick with a breakdown, rising 440/554/659 Hz pad, high-passed
  noise hats with a roll). Imported into a fresh scratch catalog; computed peaks
  stored (W2 `catalog analyze-waveform`) for tracks 1 and 2 only (`track_waveforms`
  rows verified read-only); track 3 deliberately left unanalysed. The scratch directory was bind-mounted
  at `/mnt` so no host paths appear. No private library data.
- Input: foreground pointer events into the app window; each state change was
  confirmed by a fresh capture before saving.

| File | Shows |
|---|---|
| `01-mono.png` | Track 2 selected, style Mono, gains 1.00 |
| `02-three-band.png` | Same track, style 3-band |
| `03-rgb.png` | Same track, style RGB (breakdown bars visibly lack low energy) |
| `04-rgb-low-cut.png` | RGB with Low display gain 0.00 — red/low energy removed; audio unchanged |
| `05-empty-unanalysed.png` | Track 3 selected: "No computed waveform: track not analysed" empty state |

No vendor-derived (PWV) strip is shown because this synthetic catalog has no
imported vendor analysis; that path is covered by the UI test only.

NOT DEMONSTRATED: owner's native display, accessibility/screen reader,
real-library waveform quality, realtime/playback-synchronised rendering,
GPU/presented FPS, Rekordbox visual parity.
